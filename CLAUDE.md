This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is the **Mass. Numbers** blog (www.massnumbers.us) — a data-driven blog about Massachusetts politics and policy. It is built with [Quarto](https://quarto.org/) and hosted on GitHub Pages.

## Architecture

- **`_quarto.yml`** — Quarto site configuration (title, navbar, output directory, theme, Google Analytics, social metadata)
- **`posts/`** — Blog post source directories, each named `YYYY-MM-DD-slug/` containing an `index.qmd` file and any post-specific CSV data files
- **`docs/`** — Compiled HTML output (the published site). Generated by `quarto render`; do not edit directly
- **`_data/`** — Shared data files (CSV, XLSX) organized by year subdirectories (`2020/`, `2023/`, `2024/`)
- **`_gis/`** — GIS shapefiles and GeoJSON for Massachusetts districts, towns, precincts, and neighborhoods
- **`images/`** — Site images and post preview images
- **`massnumbers.scss`** — Custom Quarto SCSS theme (Amiri font, blue header)
- **`_freeze/`** — Quarto computation cache (committed to git, including `_freeze/site_libs/`; avoids re-running R code on every render)
- **`CNAME`** — Custom domain: www.massnumbers.us

## Building the Site

Requires [Quarto CLI](https://quarto.org/docs/get-started/) (**1.9 or newer** — the committed `docs/` output is generated with Quarto 1.9; rendering with an older version reintroduces mixed-version markup and assets) and R with relevant packages (managed via `renv` — run `renv::restore()` to install them).

```bash
# Render the entire site
quarto render

# Preview with live reload
quarto preview

# Render a single post
quarto render posts/YYYY-MM-DD-slug/index.qmd
```

Output goes to the `docs/` directory which is served by GitHub Pages.

All `_freeze/` caches were regenerated by a full re-execution under Quarto 1.9
and the current `renv` package set (notably tmap 4.2). When Quarto reuses a
freeze it copies the widget libraries (leaflet, plotly, kableExtra, crosstalk,
etc.) from `_freeze/site_libs/` into `docs/site_libs/`, so **`_freeze/site_libs/`
must be committed** alongside the per-post freezes. With it tracked, a full
`quarto render` in a clean checkout reproduces every `site_libs/` bundle the
pages reference and prunes nothing; no post-render asset-restore step is
needed. If a post is re-executed and pulls in a new widget dependency, commit
the new `_freeze/site_libs/<lib>/` directory with it.

> [!NOTE]
> Two conventions keep re-execution clean and reproducible:
> - **Interactive maps:** print the `tmap` object directly (the chunk's last
>   expression) with `tmap_mode("view")` set. Do **not** wrap it in
>   `tmap_leaflet()` — that produces no output under tmap 4.2.
> - **Bayesian models:** every `stan_glm()` call passes `seed=1234` so
>   re-rendering yields stable estimates.

## Blog Post Structure

Each post `index.qmd` follows this pattern:
1. YAML front matter with title, description, author, date, and `image` for social cards/listings
2. Setup chunk loading R libraries (global `echo: false` is set in `_quarto.yml`)
3. Data loading from local CSVs or `_data/` directory
4. Prose interspersed with R code chunks producing tables and maps
5. Wide-layout chunks use `#| column: body-outset`, `#| column: page`, or `#| column: screen`

Social metadata (Open Graph, Twitter cards) is generated automatically by Quarto from the post YAML and site-level `_quarto.yml` config.

## Blogger Archive

The 95 posts from the original Blogger site (`massnumbers.blogspot.com`,
2012-11-13 to 2022-08-21) are ported into `posts/` at their original dates,
with `categories: [blogger-archive]`. The front page (`index.qmd`) and its RSS
feed exclude that category; `archive.qmd` (navbar "Archive") lists only it.
New posts must not use the category. Each ported post opens with a provenance
callout linking its Blogger permalink, and any text added since the original
(notes on vanished Fusion Tables maps, map rebuild disclosures) sits in a
`callout-note`, never in the original prose.

Porting tools and records live in `_sources/blogspot/` (not published). The
manifest `manifest.csv` tracks each post's `site_dir` and `port_status`; run
the scripts from the repository root:

```bash
# Convert every feed entry to Quarto markdown in a scratch directory
python3 _sources/blogspot/convert_post.py --out /tmp/converted

# Stage posts into posts/ (by manifest site_dir, or every pending stage-one post in a year)
python3 _sources/blogspot/stage_post.py --converted /tmp/converted 2014-03-09-fifth-middlesex-likely-blue

# Re-add the "interactive map no longer available" notes listed in stale_captions.tsv
python3 _sources/blogspot/add_caption_notes.py

# Check prose against the originals and rendered output for remote images,
# Fusion Tables URLs and provenance; --strict-links also fails leftover
# links to other Blogger posts
python3 _sources/blogspot/verify_fidelity.py --strict-links
```

`stage_post.py` overwrites the staged `index.qmd`, so re-staging a ported post
discards its hand edits (caption notes are restored by `add_caption_notes.py`;
rebuilt map chunks are not). Six posts carry rebuilt maps whose data sits
beside the post; `_sources/blogspot/fusion_tables.csv` records every Fusion
Tables reference, its fidelity tier, and the check behind it, and
`FEASIBILITY.md` the investigation and outcome.

## Commonly Used R Packages

- **tidyverse** — data wrangling (used in every post)
- **sf** / **tmap** / **tmaptools** — spatial data and interactive maps (Leaflet-based)
- **gt** / **gtExtras** — formatted tables
- **plotly** — interactive charts
- **formattable** — formatted numeric display
- **rstanarm** — Bayesian regression (used in some analytical posts)

## Content Domain

Posts analyze Massachusetts election data: precinct-level results, PVI (Partisan Voter Index) ratings, census demographics, state legislative district maps, campaign finance (OCPF) data, and special election previews. Data files use MA-specific terminology (VTDs, precincts, state rep/senate districts, congressional districts).
